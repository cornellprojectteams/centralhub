Space Status system guide

Reference for the Space Status system: what each part does, how notifications and reminders behave, and how to make changes.

Overview Components On submit Severity & deadlines Reminders Web pages Making changes Utilities Links

01Overview

The system runs on a Google Form, a Google Sheet, and one Apps Script. A form submission triggers an email to the responsible team with a deadline. Reminders repeat until the team marks the issue addressed. Each team has a status page. The sheet is the database.

Form→ Sheet→ Script→ Email→ Team marks it addressed

02Components

  • The form. Collects team, issue type, required action, severity, details, and a photo. The team dropdown must match the Team column in Team Contacts.
  • Form Responses tab. One row per submission. The script manages four columns: Notified at, Issue token, Addressed at, Last reminder. Do not edit them by hand.
  • Team Contacts tab. Liaison, team general email, safety lead, extra CC, and a team token per row. The script reads it live; edits apply to the next email.
  • The script. A standalone Apps Script project. One file: 02_notify_on_submit.gs. A copy is kept in this repo under apps-script/.
  • The web app. Served by the same script: the confirm page behind the email button and the team status pages.

03On submit

The form-submit trigger is named sendEmails and calls onFormSubmit, which:

  1. Reads the row by header name. Column order does not matter.
  2. Looks up the team in Team Contacts. To: general email and liaison. Cc: safety lead, extra CC, always-CC list.
  3. Sends the email: severity-based subject, deadline in bold, one action button.
  4. Stamps Issue token and Notified at on the row and sets any photo to link-view so the portal can display it.

If the team has no usable email, mail goes to CONFIG.fallbackEmail.

The trigger belongs to another account and cannot be deleted from this one. The script keeps a shim so it runs the current code:

function sendEmails(e) { onFormSubmit(e); }

Do not add a second on-submit trigger; teams would get duplicate mail.

04Severity and deadlines

Severity comes from the Current Status field. Teams never see the color names.

SeverityWindowWhat the team reads
RedSame dayUrgent: same-day action needed
Orange3 daysAction needed within 2 to 3 days
Yellow10 daysPlease address within 7 to 10 days
Ivory21 daysFor attention within 14 to 21 days
PurpleNoneImprovement opportunity. No deadline, no reminders.

Windows are set in SLA_DAYS, wording in SEVERITY. Both are at the top of the script:

const SLA_DAYS = { red: 0, orange: 3, yellow: 10, ivory: 21, purple: null };

const SEVERITY = {
  red: { subject: 'Urgent: same-day action needed', ... },
  ...
};

05Reminders

sendReminders runs on a daily time trigger.

  • Day 0: no reminder. The initial notice covers it.
  • Due date: first reminder.
  • After that: repeat until the issue is marked addressed, at this interval:
interval = max(1, round(windowDays / 2))  // days

Example: reported June 1, due June 5. Reminders go June 5, 7, 9, and so on. Red reminds daily. Purple never reminds. The schedule anchors to the Last reminder stamp, so a missed run self-corrects the next day.

06Web pages

Four routes on one URL:

/exec                team picker (default)
/exec?view=all       all open issues — embedded in Admin hub
/exec?view=Baja       read-only status page for one team
/exec?team=TOKEN      full portal with Mark addressed buttons
/exec?id=TOKEN        confirm page, opened by the email button

The confirm page exists because mail scanners prefetch links; a plain link would close issues on its own. Nothing changes until a person clicks confirm.

Closing an issue writes a timestamp into Addressed at. Clear that cell to reopen the issue.

07Making changes

  • Contacts and recipients: edit Team Contacts.
  • Wording, deadlines, sender: edit the constants at the top of the script and save.
  • New team: add a row in Team Contacts, run fillTeamTokens, add the name to the form dropdown.
  • Web page changes: these do not go live until you deploy a new version. Deploy → Manage deployments → pencil → Version: New version → Deploy. The URL stays the same.

Go-live settings, in CONFIG at the top of the script:

sender: 'eng_projectteams@cornell.edu',  // send-as alias on the running account
alwaysCc: ['nhh5@cornell.edu'],

08Utilities

Run from the script editor:

  • fillTeamTokens Creates tokens for teams that lack one.
  • sharePhotos One-time backfill; makes older photos viewable in the portal.
  • sendReminders Sends due reminders immediately.
  • listResponseHeaders Prints the sheet's column headers to the log.
