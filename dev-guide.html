Working on the hub

How to change the site and the scripts behind it, and how each script goes live. Everyday admin work is in the admin guide.

Get started Sandbox Edit and publish Files Apps Script projects Space Status Inventory Team photos Fabman sign-ups Command Center API

01Get started

You need a GitHub account with access to cornellprojectteams/centralhub (a 404 means ask to be added), and for a script, edit access to its Apps Script project or sheet.

  1. Open the repository, click the green Code button, then Codespaces > Create codespace on main.
  2. Wait about a minute. VS Code opens in the browser and the sandbox starts.
  3. Next time, reopen the same codespace from that menu instead of making a new one.

On your own computer instead: clone the repo and install Node.js 18 or newer.

02Sandbox

The whole platform on made-up data: every page, every web app and the sheet scripts. Emails go to an outbox. Nothing reaches Google, Fabman or a real person.

  1. In a codespace it is already running. Otherwise run:
node sandbox/server.js
  1. Open http://localhost:8080/sandbox/ (in a codespace: the globe on port 8080 in the Ports panel).
  2. Edit a file, save, refresh. Script files too; nothing to paste or deploy.

Reset the sandbox puts the fake data back. node sandbox/check.js tests everything. To try a script change on real Google with mail going only to you, follow sandbox/google/README.md.

03Edit and publish

Edit

Make the change yourself, or ask Copilot (chat icon, or Cmd/Ctrl + Shift + I). Name the file and point at something to copy, for example: "In admin.html, add a link to the fire safety doc in the Compliance section, like the other links there." Review the diff before accepting. One change at a time.

Adding a link to a page

  • Staff links go in index.html, admin links in admin.html, script and code links in developer.html.
  • Copy an existing <a class="action"> next to it: keep action-title, action-sub, and add search words in data-keywords.
  • A new admin section also needs a link in the section list (#admin-nav) and a color in styles.css (search for --cat).
  • Colors and fonts are the tokens at the top of styles.css.

Publish

git add -A
git commit -m "add fire safety link to compliance"
git push

Or use the Source Control icon: type a message, Commit, Sync Changes. The live site updates within a minute or two. Hard-refresh (Cmd/Ctrl + Shift + R) if you don't see it.

Undo

  • git status lists what changed.
  • git checkout -- file discards your edits to that file since the last commit.
  • Pushed something broken? Every version is kept in history. Ask for help before forcing anything.

A push that is rejected because GitHub has newer commits (the team photos bot commits too): run git pull --rebase, then push again.

Putting a change live

  1. Try it in the sandbox.
  2. Open the project, paste the new file over the old one, save.
  3. For a web app: Deploy > Manage deployments > pencil > Version: New version > Deploy. The URL stays the same.
  4. Commit the same file in apps-script/ so the copy matches what runs.

Setting up a new web app

  1. Paste the file into its project (or the sheet's Apps Script) and save.
  2. Deploy > New deployment > Web app. Execute as: Me. Who has access: Anyone. Plain "Anyone": with "Anyone with a Google account" the site gets a sign-in page and can't reach it.
  3. Copy the URL ending in /exec into config.js: SPACE_STATUS_URL, INVENTORY.apiUrl or TEAM_PHOTOS.refreshUrl. The Command Center URL is STATS_ENDPOINT in app.js and command-center.html.
  4. Check it: open the URL with ?action=status or ?action=list on the end. You should see a line of JSON, not a sign-in page.

06Space Status

One project sends the emails and reminders and serves every Space Status page. The Space Status Tracking sheet is its database.

How a report flows

  1. The form-submit trigger sendEmails calls onFormSubmit. It reads the row by header name.
  2. It finds the team on Team Contacts and emails it (team email and liaison; Cc safety lead, Extra CC, CONFIG.alwaysCc). No address on file: CONFIG.fallbackEmail.
  3. It stamps Issue token and Notified at and shares the photo by link.
  4. sendReminders runs daily. First reminder on the due date, then every max(1, round(windowDays / 2)) days. Approved, pending and "when time allows" rows are skipped.

The trigger belongs to another account and can't be deleted, so the script keeps function sendEmails(e) { onFormSubmit(e); }. Never add a second submit trigger: teams would get every email twice.

Settings

At the top of 02_notify_on_submit.gs: deadlines in SLA_DAYS, email wording in SEVERITY, and CONFIG (sender alias, alwaysCc, fallbackEmail, and webAppUrl, which must be the deployed URL because the email buttons use it). Proposal thresholds are in PR in 07_proposals.gs.

Pages

Functions to run by hand

  • fillTeamTokens after adding a team.
  • sendReminders to send due reminders now.
  • setupTasksProjects, setupProposals to build or repair their tabs (safe to rerun).
  • listResponseHeaders to print the form's headers.

07Inventory

The inventory sheet is the database. Its bound script, 08_inventory.gs, keeps the sheet tidy and is the app's API (JSONP; photos go up as a POST).

The sheet

  • Inventory Master: one row per item. Status, Next Maintenance and Item Link are formulas; Item ID, Date Added and Added By are filled by the script.
  • Maintenance Log, Lists (categories with ID prefix, subcategories, locations, teams in column E) and Dashboard.
  • Item IDs (PT-001) come from the category prefix and never change.

Setup and updates

  1. Paste 08_inventory.gs into the sheet's Apps Script and run setupInventory. It is safe to rerun: it adds missing columns and runs a self-test. Approve Drive access for photos.
  2. Deploy as a web app (see Setting up a new web app) into INVENTORY.apiUrl.
  3. After a code change, deploy a new version. The app's admin view warns when the sheet runs an older script.

Never run setupInventory in the old Tool inventory, purchasing and locks sheet; it refuses to, because the Command Center reads that sheet.

Team links

inventory.html?team=Baja&key=.... The key is an HMAC of the team name signed with the script property INV_TEAM_SECRET (made on first use). A link can add items to its own team and edit them, nothing else. Reset all links makes a new secret.

08Team photos

The Update button on team-photos.html asks 09_team_photos.gs to start the GitHub Action team-photos.yml. The Action runs tools/team-photos/scrape.py (opens each team page in a headless browser) and build.py (works out name, role, subteam and class year), then commits data/team-photos.json. It also runs on the 1st of each month.

Connecting the Update button (once)

  1. On GitHub: Settings > Developer settings > Fine-grained tokens. Owner cornellprojectteams, only centralhub, permission Actions: Read and write.
  2. New Apps Script project with 09_team_photos.gs. Add the token as script property GITHUB_TOKEN.
  3. Deploy it as a web app into TEAM_PHOTOS.refreshUrl.

When the token expires the page says so. Replace the script property; no redeploy needed.

What a refresh changes

  • New people are added; changed roles, photos and class years are updated.
  • People no longer on their team's site get "status": "left" (hidden as former).
  • A team whose site fails, or suddenly lists under half as many people, is left as it was.

Editing the data by hand

Edit data/team-photos.json on GitHub. Each person is one entry in people:

{ "id": "manual-jdoe1", "team": "Baja", "name": "Jane Doe", "role": "Suspension Lead",
  "roleType": "lead", "subteam": "Suspension", "classYear": 2028,
  "photo": "https://...", "status": "current", "source": "manual" }
  • roleType is lead, member or advisor. team must match tools/team-photos/sites.json.
  • "source": "manual" entries are never touched by a refresh. To keep a fix on a scraped person, add "locked": true.
  • To mark someone graduated early, set "status": "graduated".

When a team moves its page

Update the team in tools/team-photos/targets.json and sites.json, then test locally:

pip install playwright && playwright install chromium
python3 tools/team-photos/scrape.py "Mars Rover"
python3 tools/team-photos/build.py --dry-run

Drop --dry-run to write the file. --prune deletes everyone graduated or former.

09Fabman sign-ups

  • The Canvas FabMan Agreement is a Qualtrics survey. Its Google Sheets task adds a row to the FabMan Agreement tab, which fires onSheetChange in 05_fabman_members.gs. That makes the Fabman account and writes the result in Fabman status.
  • processNewSignups runs hourly and finishes anything left waiting.
  • Script properties: ALERT_EMAILS (who hears about problems; Noah if unset) and FABMAN_API_KEY (replaces the key in the code).
  • Triggers and the Qualtrics task run as whoever set them up. Use a staff account that will still exist next year: sheet menu Fabman sign-ups > Set up the sign-up triggers.
  • Columns are found by header, but Qualtrics writes by header name too: renaming the tab or a header breaks sign-ups.

10Command Center API

  • Read-only. Reads the sheets in SOURCES and returns one JSON payload.
  • Cached for 3 minutes. After a change, deploy a new version and bump CACHE_VERSION (or run clearStatsCache).
  • describeSources, peekFleetLog and peekFleetApproval print what it sees, for checking column names.
  • Mill room orders and locks come from the old Tool inventory, purchasing and locks sheet, not the inventory app.
